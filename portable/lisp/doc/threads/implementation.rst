####################
 Реализация потоков
####################

Данная реализация использует зеленые потоки, то есть кооперативную многозадачность. Потоки должны передавать управление на другие потоки в местах указанных программистом. Завершение главного потока - выход из программы.

Модуль потоков threads.c
------------------------

Этот модуль инициализирует подсистему потоков и реализует программный интерфейс для работы с потоками. Потоки хранятся в массиве threads, размером MAX_THREADS. Сначала при добавлении потоков массив заполняется последовательно, затем используется список свободных ячеек. Главный (основной) поток тоже должен быть инициализирован.

Интерпретатор Лисп
------------------

Основу интерпретатора составляет функция eval, которая выполняет заданное выражение (параметр obj) в заданном окружении переменных (параметр env). Она обходит дерево выражения и выполняет каждое подвыражение. Параметрами вычислений являются:
* текущее окружение перенных (current_env);
* текущее окружение функций (func_env);
* стек для tagbody (два окружения в каждом кадре стека);
* стек для catch (два окружения и метка в каждом кадре стека);
* стек защищенных объектов (protected).

Каждый поток должен хранить эти состояния. Глобальные переменные доступны всегда для всех потоков, поэтому их не надо учитывать. Также поток должен хранить выражение, с которого возобновится вычисление, когда поток вновь получит управление.

(progn 1 2 3 (thread-yield) 4 5 6) ;; при переключении должно сохраниться (progn 4 5 6)
(progn 1 2 3
   (if (> a 10) (thread-yield) nil)
   4 5 6)  ;; при переключении должно сохраниться (progn 4 5 6)

Переключение между потоками
---------------------------

Каждый поток должен хранить свой стек, где будет текущее состояние интерпретатора, указатель стека (регистр esp/rsp).

Состояние стека при вызове thread-yield:
::

   -------------- Кадр thread-yield
   адрес возврата
   -------------- Предыдущий кадр
   локальные переменные
   EBP/RBP - указатель предыдущего кадра
   адрес возврата
   параметры

ESP/RSP указывает на адрес возврата. EIP/RIP - внутри thread-yield. EIP/RIP не нужно сохранять, потому что адрес возврата уже хранится в стеке.

Алгоритм thread-yield:
* сохранить все параметры интерпретации (которые выше) в структуре текущего потока
* сохранить текущий ESP/RSP в структуре текущего потока
* сохранить требуемые регистры (как в setjmp)
* выбрать следующий поток для возобновления (он становится текущим)
* восстановить параметры интерпретации из структуры нового текущего потока
* восстановить регистры
* восстановить ESP/RSP

После выхода из thread-yield, управление попадает в точку после вызова thread-yield другого потока
