Введение
========

В данном документе представлен разбор файлов с расширением ``.ttf``, используемых для хранения шрифтов стандарта **TrueType**. Данный формат создан на основе контейнера **sfnt**. Важно понимать, что **TrueType** не единственная реализация шрифтов, использующая данную архитектуру.

Общие сведения
==============

Файл шрифта TrueType представляет собой последовательность соединенных таблиц. Под таблицей понимают последовательность слов. Каждая таблица выровнена по длине (в случае необходимости используется дополнения нулями).

Первой из таблиц обязательно является **каталог шрифта**, специальная таблица, облегчающая доступ к другим таблицам шрифта. За каталогом следует последовательность таблиц, содержащих данные шрифта. Они могут располагаться в любом порядке. Некоторые из них обязательны для всех шрифтов (Таблица 2). Другие могут отсутствовать (они отвечают за дополнительные возможности).

.. table:: Таблица 2

   +--------+-----------------------------------------------+
   | Тег    | Описания                                      |
   +========+===============================================+
   | 'cmap' | Сопоставляет кодировку символа и глиф индекса.|
   +--------+-----------------------------------------------+
   | 'glyf' |                                               |
   +--------+-----------------------------------------------+
   | 'head' |                                               |
   +--------+-----------------------------------------------+
   | 'hhea' |                                               |
   +--------+-----------------------------------------------+
   | 'hmtx' |                                               |
   +--------+-----------------------------------------------+
   | 'loca' |                                               |
   +--------+-----------------------------------------------+

   +--------+-----------------------------------------------+
   | 'name' |                                               |
   +--------+-----------------------------------------------+
   | 'post' |                                               |
   +--------+-----------------------------------------------+

Таблицы имеют имена, известные как теги (тип данных ``uint32``). Согласно документации в настоящий момент времени определенные имена тегов состоят из четырех символов. Имена, содержащие менее четырех символов, заканчиваются пробелами. Названия тегов, отображаемые в тексте, заключаются в прямые кавычки (``'post'``).

Каталог шрифта (The Font Directory)
====================================

Каталог шрифтов, первая из таблиц, служащая руководством по содержимому файла ``.ttf``. Он состоит из двух частей: подтаблицы смещений (*offset subtable*) и каталога таблиц (*table directory*).

Файл начинается с **подтаблицы смещений** (*offset subtable*). Первые 4 байта (*scaler type*) хранят тип масштабирования, описывающий способ извлечения глифов шрифта. Для **TrueType** (``0x74727565``) или ``0x00010000``. Первое значение рекомендовано для OS-X, второе для Windows и продуктов Adobe. Иные значения говорят, что конкретный файл относится к шрифтам иного типа.

Далее идут 2 байта (*numTables*), содержащие количество таблиц без учёта подтаблиц и самого каталога таблиц.

Остальные 6 байт содержат 3 записи, используемые для бинарного поиска в каталоге таблиц (актуально для большого числа записей).

1. **searchRange** — это наибольшая степень двойки, которая меньше или равна количеству элементов в таблице, то есть наибольшее количество элементов, которые можно легко найти с помощью поиска.
2. **rangeShift** — это количество элементов минус searchRange, то есть количество элементов, которые не будут учитываться при поиске, если рассматривать только searchRange элементов.
3. **entrySelector** показывает, сколько итераций цикла поиска необходимо выполнить.

Важно заметить, что эти 3 значения умножаются на 16.

В обобщённом виде (Таблица 3):

.. table:: Таблица 3

   +--------+-----------------+--------------------+-----------------------------------------------------------------------------------------------------+
   | Тип    | Название        | Размер в байтах    | Описание                                                                                            |
   +========+=================+====================+=====================================================================================================+
   | uint32 | scaler type     | 4                  | Хранит тип масштабирования, описывающий способ извлечения глифов шрифта. Для TrueType               |
   |        |                 |                    | (``0x74727565``) или ``0x00010000``.                                                                |
   +--------+-----------------+--------------------+-----------------------------------------------------------------------------------------------------+
   | uint16 | numTables       | 2                  | Хранит количество таблиц. В это число не входят подтаблицы и сам каталог таблиц.                    |
   +--------+-----------------+--------------------+-----------------------------------------------------------------------------------------------------+
   | uint16 | searchRange     | 2                  | Хранит наибольшую степень двойки, меньше или равную количеству элементов в таблице.                 |
   +--------+-----------------+--------------------+-----------------------------------------------------------------------------------------------------+
   | uint16 | entrySelector   | 2                  | Количество элементов минус searchRange.                                                             |
   +--------+-----------------+--------------------+-----------------------------------------------------------------------------------------------------+
   | uint16 | rangeShift      | 2                  | показывает, сколько итераций цикла поиска необходимо выполнить.                                     |
   +--------+-----------------+--------------------+-----------------------------------------------------------------------------------------------------+

Далее идёт **каталог таблиц** (*table directory*), содержащий записи о каждой таблице. Все записи имеют длину в 16 байт и отсортированы по возрастанию тега (*tag*). Каждая запись имеет следующую структуру (Таблица 4).

cmap
====

Таблица ``cmap`` отвечает за сопоставления кодировки символа и индекса глифа. В случае необходимости таблица может содержать несколько подтаблиц (для различных кодировок). Сама кодировка определяется платформой, на которой будет использован шрифт. Если символ не поддерживается шрифтом, его код сопоставлен с глифом под индексом 0. Индекс ``0xFFFF`` зарезервирован.

Таблица начинается с номера версии таблицы, за которым следует количество таблиц кодирования (Таблица 5). Далее идут подтаблицы кодирования.

.. table:: Таблица 5

   +---------+-------------------+--------------------+------------------------------------------+
   | Тип     | Название          | Размер в байтах    | Описания                                 |
   +=========+===================+====================+==========================================+
   | UInt16  | version           | 2                  | Номер версии (установить на ноль).       |
   +---------+-------------------+--------------------+------------------------------------------+
   | UInt16  | numberSubtables   | 2                  | Количество подтаблиц кодирования.        |
   +---------+-------------------+--------------------+------------------------------------------+

Подтаблица ``cmap`` состоит из трех полей (Таблица 6):

.. table:: Таблица 6

   +---------+---------------------+--------------------+------------------------------------------------------------------------------------+
   | Тип     | Имя                 | Размер в байтах    | Описания                                                                           |
   +=========+=====================+====================+====================================================================================+
   | UInt16  | platformID          | 2                  | Идентификатор платформы.                                                           |
   +---------+---------------------+--------------------+------------------------------------------------------------------------------------+
   | UInt16  | platformSpecificID  | 2                  | Идентификатор кодировки, специфичный для платформы.                                |
   +---------+---------------------+--------------------+------------------------------------------------------------------------------------+
   | UInt32  | offset              | 4                  | Смещение таблицы сопоставления. Отсчитывается от начала таблицы cmap, а не от      |
   |         |                     |                    | начала TTF-файла.                                                                  |

Подтаблицы ``cmap`` необходимо сначала отсортировать в порядке возрастания по идентификатору платформы, а затем по идентификатору, специфичному для платформы. Поля ``platformID`` и ``platformSpecificID`` используют те же значения, что и соответствующие поля в таблице ``name`` (Таблица 7).

.. table:: Таблица 7

   +-------------+--------------+----------------------+
   | Platform ID | Платформа    | Platform-specific ID |
   +=============+==============+======================+
   | 0           | Unicode      | Версия Unicode.      |
   +-------------+--------------+----------------------+
   | 1           | Macintosh    | Код менеджера скриптов.|
   +-------------+--------------+----------------------+

Существует три основных типа подтаблиц кодирования:

1. Подтаблицы Unicode
2. Подтаблицы последовательностей вариантов Unicode
3. Подтаблицы, не использующие кодировку Unicode (все остальное)

Разбор подтаблицы Unicode форматов 4 и 12
------------------------------------------

Каждая подтаблица ``cmap`` представлена в одном из девяти доступных в настоящее время форматов. Большинство из них считается устаревшими.

Формат 4
~~~~~~~~

Данный формат подтаблицы используется в случае, если некоторые коды в диапазоне не связаны с глифами шрифта. В таблице 8 приведена структура заголовка рассматриваемой подтаблицы.

.. table:: Таблица 8

   +---------+---------------+--------------------+-------------------------------------------+
   | Тип     | Имя           | Размер в байтах    | Описания                                  |
   +=========+===============+====================+===========================================+
   | UInt16  | format        | 2                  | Всегда 4 (00 04)                          |
   +---------+---------------+--------------------+-------------------------------------------+
   | UInt16  | length        | 2                  | Полный размер подтаблицы в байтах         |
   +---------+---------------+--------------------+-------------------------------------------+
   | UInt16  | language      | 2                  | Обычно 0 для Unicode                      |
   +---------+---------------+--------------------+-------------------------------------------+
   | UInt16  | segCountX2    | 2                  | Количество сегментов × 2                  |
   +---------+---------------+--------------------+-------------------------------------------+
   | UInt16  | searchRange   | 2                  | Параметр быстрого бинарного поиска        |
   +---------+---------------+--------------------+-------------------------------------------+
   | UInt16  | entrySelector | 2                  | Параметр бинарного поиска                 |
   +---------+---------------+--------------------+-------------------------------------------+
   | UInt16  | rangeShift    | 2                  | Остаток для оптимизации поиска            |
   +---------+---------------+--------------------+-------------------------------------------+

Количество сегментов задается явно не используемой в таблице формата 4 переменной ``segCount``, однако именно от нее зависят все параметры таблицы. ``segCount`` — это количество смежных диапазонов кодов в шрифте. Внутри подтаблицы данное значение хранится в переменной ``segCountX2``, равной удвоенному количеству сегментов.

Параметры ``searchRange``, ``entrySelector`` и ``rangeShift`` предназначены для оптимизации поиска. Они вычисляются на основании количества сегментов:

1. **searchRange** — наибольшая степень двойки, не превышающая ``segCount``, умноженная на 2.
2. **entrySelector** — двоичный логарифм наибольшей степени двойки, не превышающей ``segCount``.
3. **rangeShift** — разность между ``segCountX2`` и ``searchRange``.

После заголовка располагаются массивы, описывающие диапазоны кодов Unicode и соответствующие им индексы глифов. Структура подтаблицы представлена в таблице 9.

.. table:: Таблица 9

   +---------+-----------------+--------------------+--------------------------------------------------+
   | Тип     | Имя             | Размер в байтах    | Описания                                         |
   +=========+=================+====================+==================================================+
   | UInt16  | endCode         | 2 × segCount       | Массив конечных кодов сегментов                  |
   +---------+-----------------+--------------------+--------------------------------------------------+
   | UInt16  | reservedPad     | 2                  | Зарезервированное поле, всегда 0                 |
   +---------+-----------------+--------------------+--------------------------------------------------+
   | UInt16  | startCode       | 2 × segCount       | Массив начальных кодов сегментов                 |
   +---------+-----------------+--------------------+--------------------------------------------------+
   | Int16   | idDelta         | 2 × segCount       | Смещение для вычисления индекса глифа            |
   +---------+-----------------+--------------------+--------------------------------------------------+
   | UInt16  | idRangeOffset   | 2 × segCount       | Смещение до массива индексов глифов              |
   +---------+-----------------+--------------------+--------------------------------------------------+
   | UInt16  | glyphIdArray    | Переменный         | Дополнительный массив индексов глифов            |
   +---------+-----------------+--------------------+--------------------------------------------------+

   +=================+==========================================+
   | format          | 0                                        |

   +-----------------+------------------------------------------+
   | language        | 4                                        |

   +-----------------+------------------------------------------+
   | glyphIdArray    | 16 + 8 × segCount                        |

Каждый элемент массивов ``endCode``, ``startCode``, ``idDelta`` и ``idRangeOffset`` занимает два байта, их индексы начинаются с 0.

Массив ``endCode`` содержит конечные коды каждого сегмента. Значения расположены в порядке возрастания. Последний сегмент обычно имеет конечный код ``0xFFFF``, который служит завершающим элементом. Массив ``startCode`` содержит начальные коды соответствующих сегментов. Таким образом, сегмент с индексом (i) описывает диапазон от ``startCode[i]`` до ``endCode[i]`` включительно. Например, если ``startCode[0] = 0x0041``, а ``endCode[0] = 0x005A``, то данный сегмент описывает символы латинского алфавита от A до Z.

Массив ``reservedPad`` содержит два нулевых байта. Данное поле необходимо для соблюдения структуры формата и не участвует в вычислении индексов глифов.

Вычисление индекса глифа
~~~~~~~~~~~~~~~~~~~~~~~~~

Для определения индекса глифа по коду Unicode сначала необходимо найти сегмент, в диапазон которого входит код символа ``c``. Для этого проверяется условие:

``startCode[i] <= c <= endCode[i]``

После нахождения подходящего сегмента используется массив ``idDelta`` или ``idRangeOffset``.

Массив ``idDelta`` содержит знаковые 16-битные значения, которые позволяют вычислить индекс глифа непосредственно из кода символа. Если соответствующий элемент ``idRangeOffset[i]`` равен нулю, применяется формула:

::

   glyphIndex = (c + idDelta[i]) mod 65536

Если ``idRangeOffset[i]`` не равен нулю, индекс глифа необходимо получить из массива ``glyphIdArray``. При этом важно учитывать, что ``idRangeOffset`` содержит не абсолютное смещение, а относительное смещение в байтах от адреса самого поля ``idRangeOffset[i]`` до соответствующего элемента массива индексов глифов.

Пусть ``pi`` — смещение поля ``idRangeOffset[i]`` относительно начала подтаблицы. Тогда адрес нужного элемента вычисляется следующим образом:

::

   p_glyph = pi + idRangeOffset[i] + 2 * (c - startCode[i])

По этому адресу читается 16-битный индекс глифа. Если прочитанное значение равно нулю, символ не сопоставляется с глифом. В противном случае к прочитанному значению применяется ``idDelta``:

::

   glyph_Index = (glyph_Id + idDelta[i]) mod 65536

Формат 12
~~~~~~~~~

Формат 12 используется для сопоставления кодов Unicode с индексами глифов в виде групп непрерывных диапазонов. В отличие от формата 4, он поддерживает коды за пределами базовой многоязычной плоскости Unicode, то есть значения выше ``0xFFFF``.

Данный формат используется для шрифтов, содержащих символы дополнительных плоскостей Unicode, например некоторые математические символы.

Структура заголовка подтаблицы формата 12 представлена в таблице 11.

.. table:: Таблица 11

   +---------+-------------+--------------------+-------------------------------------------+
   | Тип     | Имя         | Размер в байтах    | Описания                                  |
   +=========+=============+====================+===========================================+
   | UInt16  | format      | 2                  | Всегда 12 (00 0C)                         |
   +---------+-------------+--------------------+-------------------------------------------+
   | UInt16  | reserved    | 2                  | Зарезервированное поле, всегда 0          |
   +---------+-------------+--------------------+-------------------------------------------+
   | UInt32  | length      | 4                  | Полный размер подтаблицы в байтах         |
   +---------+-------------+--------------------+-------------------------------------------+
   | UInt32  | language    | 4                  | Идентификатор языка                       |
   +---------+-------------+--------------------+-------------------------------------------+
   | UInt32  | numGroups   | 4                  | Количество групп кодов                    |
   +---------+-------------+--------------------+-------------------------------------------+

После заголовка располагается массив групп. Каждая группа занимает 12 байт и содержит три 32-битных значения (Таблица 12).

.. table:: Таблица 12

   +---------+----------------+--------------------+-------------------------------------------+
   | Тип     | Имя            | Размер в байтах    | Описания                                  |
   +=========+================+====================+===========================================+
   | UInt32  | startCharCode  | 4                  | Первый код Unicode в группе               |
   +---------+----------------+--------------------+-------------------------------------------+
   | UInt32  | endCharCode    | 4                  | Последний код Unicode в группе            |
   +---------+----------------+--------------------+-------------------------------------------+
   | UInt32  | startGlyphID   | 4                  | Индекс глифа для первого кода группы      |
   +---------+----------------+--------------------+-------------------------------------------+

Общий размер подтаблицы формата 12 вычисляется по формуле:

::

   length = 16 + 12 * numGroups

Начало каждой последующей группы определяется по формуле:

::

   pi = 16 + 12 * i

где ``i`` — индекс группы, начинающийся с нуля.

Вычисление индекса глифа в формате 12
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

В формате 12 каждая группа описывает непрерывный диапазон кодов Unicode. Значение ``startGlyphID`` задаёт индекс глифа для первого символа диапазона, а индексы остальных глифов вычисляются последовательным увеличением этого значения.

Для кода символа ``c``, принадлежащего группе ``i``, индекс глифа определяется формулой:

::

   glyph_Index = startGlyphID[i] + (c - startCharCode[i])

Для поиска нужной группы массив просматривается с использованием бинарного поиска. Группы упорядочены по возрастанию ``startCharCode``, а их диапазоны не должны пересекаться.
