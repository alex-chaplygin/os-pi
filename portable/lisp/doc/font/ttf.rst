Введения
========

В данном документе представлен разбор файлов с расширением ``ttf``, используемых для хранения шрифтов стандарта ``TrueType``. Данный формат создан на основе контейнера ``sfnt``. Важно понимать, что ``TrueType`` не единственная реализация шрифтов, использующая данную архитектуру.

Согласно официальной документации, размещённой на сайте разработчика, в дополнение к стандартным целочисленным типам данных, формат шрифта TrueType использует следующие (Таблица 1).

Общие сведения
--------------

Файл шрифта TrueType представляет собой последовательность соединенных таблиц. Под таблицей понимают последовательность слов. Каждая таблица выровнена по длине (в случаи необходимости используется дополнения нулями).

Они могут располагаться в любом порядке. Некоторые из них обязательны для всех шрифтов ( таблица 2 ). Другие могут отсутствовать (они отвечают за дополнительные возможности).

Таблица 2

Таблицы имеют имена, известные как теги ( тип данных ``uint32`` ). Согласно документации в настоящей момент времени определенные имена тегов состоят из четырех символов. Имена, содержащие менее четырех символов, заканчиваются пробелам(и). Названия тегов, отображаемые в тексте, заключаются в прямые кавычки ( ``'post'`` ).

Каталог шрифта ( The Font Directory )
-------------------------------------

Каталог шрифтов, первая из таблиц, служащая руководством по содержимому файла ``ttf``. Он состоит из двух частей: подтаблицы смещений ( offset subtable ) и каталога таблиц ( table directory ). 

Файл начинается с подтаблицы смещений ( offset subtable) . Первые 4 байта ( scaler type ) хранят тип масштабирования, описывающий способ извлечения глифов шрифта. Для ``TrueType`` (``0x74727565``) или ``0x00010000``. Первое значение рекомендовано для ``OS-X``, второе для ``Windows`` и продуктов ``Adobe``. Иные значения говорят, что конкретный файл относится к шрифтам иного типа .

Далее идут 2 байта ( numTables ), содержащие количество таблиц без учёта подтаблиц и самого каталог таблиц. 

Остальные 6 байт содержат 3 записи, используемые для бинарного поиска в каталоге таблиц (актуально для большого числа записей).

1. searchRange — это наибольшая степень двойки, которая меньше или равна количеству элементов в таблице, то есть наибольшее количество элементов, которые можно легко найти с помощью поиска.
2. rangeShift — это количество элементов минус searchRange, то есть количество элементов, которые не будут учитываться при поиске, если рассматривать только searchRange элементов.
3. entrySelector показывает, сколько итераций цикла поиска необходимо выполнить. 

Важно заметить, что эти 3 значения умножаются на 16

В обобщённом виде ( таблица 3 ) :

+--------+----------------+-----------------+---------------------------------------------------------------------------------------------------+
| Тип    | Название       | Размер в байтах | Описание                                                                                          |
+========+================+=================+===================================================================================================+
| uint32 | scaler type    | 4               | Х ранит тип масштабирования, описывающий способ извлечения глифов шрифта. Для TrueType            |
|        |                |                 | (0x74727565) или 0x00010000.                                                                      |
+--------+----------------+-----------------+---------------------------------------------------------------------------------------------------+
| uint16 | numTables      | 2               | Хранит к оличество таблиц. В это число не входят подтаблицы и сам каталог таблиц.                 |
+--------+----------------+-----------------+---------------------------------------------------------------------------------------------------+
| uint16 | searchRange    | 2               | Хранит наибольшую степень двойки, меньше или равную количеству элементов в таблице.               |
+--------+----------------+-----------------+---------------------------------------------------------------------------------------------------+
| uint16 | entrySelector  | 2               | Количество элементов минус searchRange.                                                           |
+--------+----------------+-----------------+---------------------------------------------------------------------------------------------------+
| uint16 | rangeShift     | 2               | Показывает, сколько итераций цикла поиска необходимо выполнить.                                   |
+--------+----------------+-----------------+---------------------------------------------------------------------------------------------------+

Таблица 4

cmap
----

Таблица ``cmap`` отвечает за сопоставления кодировки символа и индекса глифа. В случаи необходимости таблица может содержать несколько подтаблиц ( для различных кодировок ). Сама кодировка определяется платформой, на которой будет использован шрифт. Если символ не поддерживается шрифтом, его код сопоставлен с глифом под индексам 0. Индекс ``0xFFFF`` зарезервирован. 

Таблица начинается с номера версии таблицы, за которым следует количество таблиц кодирования (таблица 5). Далее идут подтаблицы кодирования.

+--------+-----------------+-----------------+-------------------------------------+
| Тип    | Название        | Размер в байтах | Описания                            |
+========+=================+=================+=====================================+
| UInt16 | version         | 2               | Номер версии (установить на ноль) . |
+--------+-----------------+-----------------+-------------------------------------+
| UInt16 | numberSubtables | 2               | Количество подтаблиц кодирования .  |
+--------+-----------------+-----------------+-------------------------------------+
